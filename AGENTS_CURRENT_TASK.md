- Android `NT_ARM_HW_WATCH` writes must size the `iovec` to the watchpoint slot count reported in `dbg_info`; writing all 16 architectural slots returned `ENOSPC` on the test device.
- Linux/Android ptrace watchpoint handling no longer uses a timer path that globally pauses every traced thread to suppress/re-arm hot watchpoints. On a watchpoint hit, the backend records the event, temporarily suppresses the hit breakpoint in stored state, reapplies watchpoints only to the stopped event thread, and immediately continues that thread. This trades repeated hit counts from the same hot thread for not bricking the process.
- The ptrace event loop now best-effort continues a stopped event thread even when breakpoint recording, register reads, or watchpoint reapply fails. This is important because a failed event path can otherwise leave the thread in kernel `t (tracing stop)` while the UI still shows the trace as running. `resume()` also drains internally marked stopped threads even if the session state already says `Running`.
- `DebuggerTraceStartRequest` now performs the attach internally before arming the trace breakpoint, so the GUI no longer dispatches a separate attach command that can strand the target in a paused ptrace state before trace-start runs. The GUI pending trace prompt now sends one trace-start command and labels the action `Start`.
